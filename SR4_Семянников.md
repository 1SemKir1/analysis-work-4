## 1. Характеристика объекта

*   **Название:** Notepad++ (версия 8.8.8, 64-bit).
*   **Назначение:** Notepad++ — это бесплатный текстовый редактор с открытым исходным кодом, предназначенный для редактирования кода и обычного текста. Он позиционируется как более функциональная замена стандартному «Блокноту» Windows.
*   **Основные функции:**
    *   Подсветка синтаксиса для большого числа языков программирования.
    *   Сворачивание кода (folding).
    *   Поддержка множества кодировок (UTF-8, ANSI, UTF-16 и др.).
    *   Работа с вкладками (multi-tab).
    *   Поиск и замена с поддержкой регулярных выражений.
    *   Плагины (Plugin Admin) для расширения функциональности.
*   **Предполагаемые пользователи:** Программисты, системные администраторы, веб-разработчики, студенты технических специальностей и продвинутые пользователи ПК, работающие с текстовыми файлами и логами.
*   **Источник и версия:** Репозиторий GitHub: `https://github.com/notepad-plus-plus/notepad-plus-plus`, версия `v8.8.8` (сборка от 16.11.2025).

## 2. Цель анализа

Цель анализа — оценить надежность и безопасность работы Notepad++ при обработке файлов с различными кодировками (в частности, CJK-символов в больших файлах), а также проверить стабильность работы функции поиска и общую сопровождаемость кода на основе публичных отчетов об ошибках.

## 5. Выявленные проблемы

В ходе анализа обнаружены следующие замечания и риски:

1.  **Критическая потеря данных при работе с CJK-символами (Баг №17234).**
    *   *Критерий:* Функциональная корректность / Обработка ошибок.
    *   *Подтверждение:* В GitHub Issue #17234 описан сценарий: при открытии большого UTF-8 файла с корейскими/китайскими символами (размером >200 КБ) Notepad++ ошибочно определяет кодировку как Windows-1252. Если пользователь прокрутит файл вниз (символы отображаются как «кракозябры») и нажмет «Сохранить», файл безвозвратно перезаписывается в неверной кодировке. 
    *   *Личное подтверждение:* В ходе собственного теста при смене кодировки с UTF-8 на ANSI кириллические символы превратились в нечитаемый набор символов, что подтверждает риск потери данных при неверной интерпретации (см. файл `screenshot_test.png` в репозитории).
    *   *Последствия:* Полная потеря данных.
    *   *Рекомендация:* Исправить логику автоопределения кодировки для больших файлов или добавить предупреждение при попытке сохранения файла с подозрительными символами.

2.  **Неочевидное поведение поиска (Баг №17227).**
    *   *Критерий:* Удобство использования (UX).
    *   *Подтверждение:* В Issue #17227 описано, что при копировании текста из Excel (где в конце ячейки есть невидимый символ перевода строки) в поле «Найти», Notepad++ перестает находить совпадения. Пользователь не видит этот символ и не понимает, почему поиск не работает.
    *   *Последствия:* Снижение производительности труда, ложное впечатление, что текст отсутствует в файле.
    *   *Рекомендация:* Добавить визуальную индикацию (например, подсветку) невидимых управляющих символов в поле поиска.

3.  **Уязвимости безопасности (CVE).**
    *   *Критерий:* Безопасность.
    *   *Подтверждение:* Согласно базе CVE, в Notepad++ (до версии 8.9.6.1) обнаружено несколько уязвимостей с высоким рейтингом (CVSS 7.8), связанных с переполнением буфера (Out-of-bounds Write) и проблемами с путями (Path Traversal).
    *   *Последствия:* Потенциальная возможность выполнения произвольного кода при открытии специально сформированного файла или использовании плагинов.
    *   *Рекомендация:* Обновиться до последней версии (8.9.6.4+), где данные уязвимости закрыты.

4.  **Ограничения при работе с большими файлами.**
    *   *Критерий:* Производительность.
    *   *Подтверждение:* Анализ сообщества показывает, что при открытии файлов размером более 100-200 МБ редактор может «зависать» на длительное время. В отличие от специализированных инструментов (EmEditor, Vim), Notepad++ загружает файл в память, что приводит к высокому потреблению ОЗУ и блокировке интерфейса.
    *   *Последствия:* Невозможность работы с большими логами или дампами.
    *   *Рекомендация:* Использовать потоковое чтение (streaming) для файлов большого размера или рекомендовать пользователям альтернативы для работы с гигантскими файлами.

5.  **Нестабильность работы с плагинами (зависание на Perl).**
    *   *Критерий:* Обработка ошибок / Сопровождаемость.
    *   *Подтверждение:* В версии 8.8.7 был зафиксирован баг (Issue #17152), при котором переключение на вкладку с файлом Perl вызывало зависание приложения на 20-30 секунд из-за ошибки в регулярном выражении в файле конфигурации Function List.
    *   *Последствия:* «Зависание» интерфейса, раздражающий фактор.
    *   *Рекомендация:* Провести ревью и оптимизацию регулярных выражений в конфигурационных файлах парсеров функций.

## 7. Итоговое заключение

В результате комплексного анализа Notepad++ было установлено, что, несмотря на свою популярность и удобный интерфейс, редактор имеет серьезные проблемы с безопасностью (наличие CVE) и потенциально критические баги, приводящие к потере данных при работе с азиатскими кодировками (CJK). Наиболее опасным является сценарий, описанный в Issue #17234, где простое действие «Сохранить» после прокрутки файла может уничтожить исходный текст.

**Ограничения исследования:** Анализ проводился на основе публичных отчетов об ошибках и баз данных уязвимостей. Мы не проводили активного тестирования (fuzzing) самого приложения, поэтому список проблем может быть неполным. Также не анализировалась безопасность сторонних плагинов, доступных через Plugin Admin.
